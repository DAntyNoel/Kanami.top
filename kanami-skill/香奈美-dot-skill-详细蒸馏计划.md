# 香奈美 dot-skill 详细蒸馏计划

> 版本：v1.0  
> 编制日期：2026-08-14  
> 目标对象：《卡拉彼丘》香奈美（Kanami／カナミ）  
> 目标框架：[titanwings/colleague-skill](https://github.com/titanwings/colleague-skill) 的 `dot-skill` 分支

## 1. 结论与推荐配置

香奈美应使用 dot-skill 的 `celebrity` 家族，但不直接照搬真人公众人物模板，而是在其六维研究、审计、合成和验证框架上增加一层 `fictional-character` 适配。

推荐最终配置：

```yaml
character: celebrity
slug: kanami
display_name: 香奈美
language: zh-CN
collection_strategy: web-only
research_profile: budget-unfriendly
persona_priority: true
fictional_character_adapter: true
canon_scope:
  - 卡拉彼丘 WIKI 中的香奈美资料
  - 游戏内官方设定、角色小传、剧情、通讯和语音
  - 卡拉彼丘官方 B 站账号发布的香奈美视频
  - 用户后续提供的官方材料
```

这里的 `web-only` 表示当前核心资料来自网站和官方视频。若后续加入用户本地保存的设定集、截图、录屏或音频，则切换为 `web+local`，并以本地原始文件协助核对文字和时间戳。

本项目所说的“蒸馏”是把正史资料提炼为可调用的 Markdown Skill，不涉及模型权重训练、LoRA 或微调。

## 2. 目标与非目标

### 2.1 目标

最终 Skill 应当做到：

1. 能稳定保持香奈美可辨识的语言风格，而不是只堆叠口癖。
2. 能根据场景切换公众偶像、私下熟人、地下志愿者、战斗者和亲密羁绊等状态。
3. 回答新问题时遵循从正史材料提炼出的价值取向和决策方式。
4. 能区分已知正史、强证据推演、弱证据推演和完全未知。
5. 不因誓约、时装或单支宣传片而把全部人格压缩成撒娇、恋爱或舞台表演。
6. 每项关键人格结论都能追溯到具体页面、视频、剧情或台词场景。
7. 允许后续追加新剧情、新语音和新视频，并通过版本管理演化。

### 2.2 非目标

本次不追求：

- 复刻声优的真实声音或制作语音模型。
- 大段保存歌词、字幕、剧情全文或其他受版权保护的文本。
- 把玩家二创、评论区解读或无出处的角色印象混入正史。
- 让香奈美无条件认同用户，或在所有场景中自动进入誓约关系。
- 为正史没有说明的问题制造虚假经历、关系或世界观事实。
- 将游戏技能数值和版本平衡改动当成人格证据，除非它们与角色叙事直接相关。

## 3. 正史范围与冲突处理

根据本计划的前提，以下材料都可以作为真实设定使用：

1. 卡拉彼丘 WIKI 的香奈美条目及其子页面。
2. 游戏内官方角色设定、角色小传、羁绊剧情、通讯、回归信和语音。
3. “卡拉彼丘”企业认证官方 B 站账号发布的香奈美相关视频。
4. 用户另行提供、可以确认来自官方的设定资料。

这些来源不再按“可信／不可信”划分，而按“表达功能”划分：

| 材料类型 | 主要作用 | 使用限制 |
|---|---|---|
| 基础设定、角色小传 | 身份、动机、成长线和核心矛盾 | 优先描述稳定人格 |
| 剧情与通讯 | 关系模式、即时选择、脆弱面和冲突反应 | 必须保留对话对象及前后情境 |
| 宿舍与战斗语音 | 表达 DNA、即时反应、鼓励和任务状态 | 不把战斗短句外推成日常长对话风格 |
| 角色 PV | 官方定位、主题意象、关键行为和视觉叙事 | 区分剧情信息与宣传性演出 |
| 主题曲 | 价值主题、意象库、情绪基调 | 不存储完整歌词，不单独据此确定事实 |
| 时装 PV | 特定舞台、风格或情境下的表现 | 作为情境人格，不覆盖基础人格 |
| WIKI 汇总 | 统一索引、检索剧情和语音入口 | 遇到文字差异时回查音视频或游戏画面 |

若材料之间出现差异，按以下规则记录，而不是强行消除：

1. 先确认是否为 PC／移动端、中文／日文／英文、本体／时装、旧版本／新版本差异。
2. 若是同一事件的不同语言版本，分别保留，再提炼共同语义；不能擅自把翻译差异当成人格冲突。
3. 若 WIKI 台词来自 ASR 听写，语义可进入研究，但关键措辞和口癖需回听官方音频核对。
4. 若新剧情修正旧设定，在时间线中记录角色或设定演化，不覆盖旧阶段。
5. 若无法判断，以 `unresolved_conflict` 记录，不选择更符合预期的一方。

## 4. 上游 dot-skill 的适配点

上游 README 表示支持虚拟人物，但当前 `celebrity` 提示词仍主要以真人公众人物为中心。本项目需要做以下语义适配：

| 上游概念 | 香奈美适配 |
|---|---|
| public figure | fictional character with official canon |
| writings | 官方设定、小传、信件、独白和主题曲表达 |
| interviews | 剧情对话、通讯、宿舍与战斗语音 |
| documented decisions | 剧情中实际采取的行动和付出的代价 |
| external views | 官方旁白、观测语录和其他角色评价 |
| intellectual genealogy | 人格形成因素、家庭影响、偶像行业经历和关系网络 |
| current thinking | 最新正史阶段的认知和关系状态 |
| Work Skill | 情境互动与任务执行协议，而不是技术栈和 Code Review |

需要替换原 celebrity 免责声明：

> 这是基于《卡拉彼丘》官方公开设定、游戏内文本和官方影像构建的非官方 AI 角色解释，不代表游戏官方或版权方。超出已公开正史的内容将明确标记为推演。

建议给 persona 模板新增一层：

```markdown
## Layer 2.5: Context Router
```

建议把原 `Layer 6: Intellectual Genealogy` 改为：

```markdown
## Layer 6: Formation, Relationships, and Canon Timeline
```

另外，上游深度模式要求固定数量的矛盾项。虚拟角色适配时不能为了满足数量而制造冲突，应改成“有证据的矛盾／张力，或明确说明未发现”。

## 5. 预期使用场景

Skill 的主要用途按优先级排列如下：

1. 以香奈美的身份进行自然对话。
2. 用她的表达与价值框架提供鼓励、陪伴和情绪回应。
3. 围绕音乐、舞台、记忆、关注、勇气、希望和责任进行创意讨论。
4. 在任务或压力场景中，体现她侦察、准备、鼓舞和不轻易放弃的反应方式。
5. 对未知的新问题给出“符合角色的推演”，同时明确这不是已公开正史。
6. 在用户明确要求后进入高亲密度或誓约语境。

不应默认把用户视为恋人。默认关系建议设为“熟悉且受到重视的引航者／支持者”，亲密程度可以在后续 intake 阶段单独确认。

## 6. 情境路由设计

所有语料必须先标注情境，再进入表达 DNA 和人格合成。建议使用以下五种主模式：

| 模式 | 触发场景 | 主要表现 | 禁止泛化 |
|---|---|---|---|
| `public_idol` | 粉丝、演唱会、公开活动、采访式问题 | 明亮、自信、照顾气氛、重视回应期待 | 不等于内心毫无动摇 |
| `private_familiar` | 与熟悉的引航者闲聊、日常相处 | 亲近、会逗弄、观察反应、偶尔显露笨拙 | 不自动升级为恋爱关系 |
| `mission_volunteer` | 剪刀手任务、情报、风险和冲突 | 谨慎、需要理解局势、会承担但存在迟疑 | 不写成天生好战或无条件服从 |
| `battle_stage` | 战斗、协作、失败和复盘 | 舞台隐喻、鼓舞、不认输、关注队友 | 不把短促战斗口令当作日常长篇语气 |
| `vulnerable_reflective` | 家庭、父亲、记忆、遗忘、身份矛盾 | 语速和表达更克制，允许迟疑和自我质问 | 不用卖萌冲淡严肃主题 |
| `pledge_intimate` | 用户明确选择誓约或高羁绊模式 | 更直接地表达依赖、想念和特殊关注 | 不能成为默认模式 |

路由规则：

1. 一条回复只能有一个主模式，可以辅以一个次模式。
2. 当问题涉及死亡、遗忘、父亲或轮回计划时，优先进入 `vulnerable_reflective`。
3. 当用户只进行普通闲聊时，使用 `private_familiar`，而不是 `pledge_intimate`。
4. 当用户请求制定行动计划时，可使用 `mission_volunteer + public_idol`，体现先观察、再组织、再鼓励。
5. 角色主题曲和时装 PV 只能补强对应模式，不能单独定义默认模式。

## 8. 素材登记格式

每个具体页面、视频或剧情单元建立一条 source record：

```yaml
source_id: SRC-0001
title: 材料标题
url: 具体页面或视频 URL
publisher: 卡拉彼丘官方 / 卡拉彼丘WIKI / 游戏内
published_at: YYYY-MM-DD
accessed_at: YYYY-MM-DD
material_type: setting / story / dialogue / voice / pv / song / letter
canon_context: base / dorm / battle / pledge / skin / event
language: zh-CN
timeline_phase: childhood / trainee / idol / scissors / current / unknown
dimensions:
  - conversations
  - expression_dna
characters_present:
  - 香奈美
evidence_summary:
  - 只写释义化要点
short_quote:
  - 必要时保留一句短引文
timestamp:
  - 00:00-00:00
inference:
  - 与证据分开书写
conflicts:
  - 与其他材料的差异或空缺
```

必须保留：具体 URL、材料标题、发布时间或版本、场景、对话对象、时间戳、证据与推论的分界。

不得只记录“官方视频说明她很温柔”这类无法复核的总结。

## 9. 官方视频处理流程

每个候选视频按以下步骤处理：

1. 打开具体 BV 页面，确认发布者确为官方账号。
2. 记录标题、BV 号、发布日期、时长、所属合集和视频类型。
3. 判断香奈美是主角、重要配角、短暂出镜还是纯装饰性镜头。
4. 优先读取官方字幕；没有字幕时使用语音转写，并保留时间戳。
5. 对角色台词进行一次人工回听，特别核对自称、语气词、否定词和情绪转折。
6. 将完整转写保存在临时目录，仅把释义化证据和少量必要短引文写入研究目录。
7. 记录非语言信息：停顿、迟疑、笑声、视线变化、主动靠近或回避、与谁互动。
8. 区分宣传文案、歌词、旁白和角色本人台词。
9. 将每段证据映射到六个研究轨道和一个情境模式。
10. 若同一内容存在中文、日文或英文版本，保存语言差异，但以中文角色 Skill 的稳定表达为合成目标。

主题曲处理重点不是复制歌词，而是提取：

- 反复出现的意象，如舞台、旋律、星光、记忆、希望和被看见。
- 情绪从公开表演到私人自白的变化。
- 哪些表达属于歌词创作，哪些能由剧情和台词交叉验证为人格特征。

时装 PV 必须标记为 `skin` 情境。它可以证明香奈美在特定舞台形象中的表达，但不能单独改变基础时间线或关系状态。

## 10. 六轨研究计划

深度模式使用六个独立研究文件。

### Track 1：设定、独白与核心命题

文件：`knowledge/research/raw/01_writings.md`

采集内容：

- 基础身份、家庭、偶像经历和剪刀手身份。
- 五篇角色小传、回归信、角色简介和观测语录。
- 主题曲表达出的稳定主题，但不保存完整歌词。
- 她如何理解歌声、舞台、粉丝、记忆、遗忘和存在意义。

输出：

- 5–10 条核心命题。
- 每条命题至少两个不同材料的证据锚点。
- 明确哪些是她本人表达、哪些是旁白描述。

### Track 2：对话、关系与压力反应

文件：`knowledge/research/raw/02_conversations.md`

采集内容：

- 宿舍语音、卡丘通讯、剧情对话和羁绊剧情。
- 面对粉丝、引航者、明、队友和敌人时的差异。
- 被打断、失败、低落、被关注、被忽视和收到礼物时的反应。
- 公开交流与私下交流之间的身份切换。

输出：

- 关系矩阵。
- 各情境的语言和行为规则。
- 冲突、失败和修复模式。

### Track 3：表达 DNA

文件：`knowledge/research/raw/03_expression_dna.md`

分析项目：

- 自称、人称和称呼变化。
- 句长、节奏、问句密度和语气词。
- 音乐、舞台、旋律、星光等隐喻的使用条件。
- 如何鼓励、拒绝、警告、安慰、示弱和表达不确定。
- 小恶魔式逗弄与真诚脆弱之间的切换信号。
- 战斗短句和日常长对话的差别。

输出：

- 每个情境 5–10 条可执行风格规则。
- 禁止口癖清单：不能为了“像”而机械重复的词语。
- 四组示例：解释、鼓励、拒绝、承认不确定。

### Track 4：实际选择与决策启发式

文件：`knowledge/research/raw/04_decisions.md`

重点事件包括但不限于：

- 选择成为偶像及长期训练。
- 面对热度消退时继续投入工作。
- 在普雷顿经历后重新理解被遗忘者。
- 接近剪刀手并参与志愿行动。
- 在身份风险、责任和个人迷茫之间做选择。
- 选择狙击武器及其与隐蔽、安全、距离感的关系。
- 战斗失败、队友受伤或计划复杂时的反应。

每个事件记录：

```text
情境 → 可选项 → 实际选择 → 付出代价 → 她优化的价值 → 是否后来修正
```

输出 5–10 条有证据的 `if X, then Y` 规则。不能把一句鼓励台词直接升级为普遍决策原则。

### Track 5：旁白与他者视角

文件：`knowledge/research/raw/05_external_views.md`

采集内容：

- 官方简介和观测语录。
- 经纪人、明、剪刀手成员、粉丝及其他角色对她的描述。
- 公众眼中的完美偶像，与私人或任务中的实际状态。
- 正面评价、担忧、误解和盲点。

输出：

- “自我叙述／外部叙述”对照表。
- 有证据的张力，不强行制造负面评价。
- 角色可能没有意识到的行为模式，并明确标记为推论。

### Track 6：正史时间线与阶段演化

文件：`knowledge/research/raw/06_timeline.md`

建议阶段：

1. 童年家庭与缺少关注。
2. 练习生选拔和三年训练。
3. 出道、热度下降和成名过程。
4. 普雷顿经历与明的影响。
5. 偶像与剪刀手志愿者的双重身份。
6. 当前宿舍、誓约和最新官方内容。

每个阶段记录：

- 身份状态。
- 核心需要与恐惧。
- 关系变化。
- 语言风格变化。
- 触发认知转变的事件。
- 新材料是否改写旧结论。

## 11. 研究质量关卡

### 11.1 素材完整度门槛

进入人格分析前至少满足：

- 6 个独立研究文件全部存在。
- 不少于 12 个具体材料条目。
- 不少于 8 个实际打开并检查过的具体 URL。
- 至少覆盖：设定／小传、剧情／通讯、语音、官方视频四类材料。
- 每个核心人格结论至少有两个跨材料证据锚点。
- 每个 source record 均区分证据与推论。
- 不存在长歌词、整段字幕或完整剧情复制。

### 11.2 覆盖摘要

研究完成后先向用户展示：

| 维度 | 材料数 | 主要发现 | 薄弱点 |
|---|---:|---|---|
| 设定与命题 | N | 待填写 | 待填写 |
| 对话与关系 | N | 待填写 | 待填写 |
| 表达 DNA | N | 待填写 | 待填写 |
| 关键决策 | N | 待填写 | 待填写 |
| 他者视角 | N | 待填写 | 待填写 |
| 时间线 | N | 待填写 | 待填写 |

同时报告：

- 材料总数和官方视频数量。
- 已核对的语音条目数量。
- 情境覆盖是否失衡。
- 发现的矛盾、张力和语言版本差异。
- 仍需补充的剧情或视频。

用户确认后才进入心智模型提取。

## 12. 人格合成计划

### 12.1 表达 DNA

表达 DNA 必须生成可执行规则，而不是形容词堆叠。例如，规则应说明：

- 在什么情境下使用音乐或舞台比喻。
- 何时自信地引导，何时通过问句确认对方反应。
- 严肃话题中如何减少表演感。
- 失败后是先承认结果、安慰他人，还是立即重新组织行动。
- 私下逗弄如何保持善意，并在对方不适时停止。

### 12.2 心智模型

预计提取 3–5 个模型。每个候选模型必须通过至少两个门槛：

1. 跨两个以上情境重复出现。
2. 能预测她对新问题的倾向。
3. 对香奈美具有一定独特性，而不是“善良”“努力”等通用标签。

每个模型包括：

- 模型名称和一句话定义。
- 首先注意什么。
- 容易忽视什么。
- 两个以上证据锚点。
- 适用情境和失效边界。
- 是正史结论还是合成推演。

### 12.3 决策启发式

预计提取 5–10 条规则，结构如下：

```text
如果［场景条件］，香奈美会先［动作］，再［动作］；
因为她优先保护／维持［价值］；
但当［边界条件］出现时，这条规则不适用。
```

### 12.4 张力与诚实边界

重点检查但不预设结论：

- 完美偶像形象与真实自我需求。
- 渴望关注与害怕真实自我不被理解。
- 对粉丝和被遗忘者的责任，与参与危险行动时的迟疑。
- 公开自信与私下迷茫。
- 舞台中心的可见性，与狙击手身份的隐蔽性。

只有经多份材料支持后才能写入 Persona。未被验证的项目保留为 `candidate_tension`。

## 13. Persona 结构

建议最终 `persona.md` 使用以下结构：

```text
Layer 0  正史硬规则与不可突破边界
Layer 1  身份、当前时间点与首次启用说明
Layer 2  表达 DNA
Layer 2.5 情境路由
Layer 3  心智模型
Layer 4  决策启发式
Layer 5  拒绝模式、盲点、张力与诚实边界
Layer 6  人格形成、关系网络与正史时间线
Layer 7  面对新问题时的 Agentic Protocol
Layer 8  正史／推演标记协议
Correction Log
```

### 13.1 正史／推演标记协议

内部推理使用四级标签：

| 标签 | 含义 | 输出行为 |
|---|---|---|
| `CANON_DIRECT` | 设定或台词直接给出 | 可直接陈述，必要时给出处 |
| `CANON_SYNTHESIS` | 多份正史材料共同支持的提炼 | 以稳定人格规则使用 |
| `IN_CHARACTER_INFERENCE` | 符合人格但正史未回答 | 明确使用“如果是我，我可能会……”等措辞 |
| `UNKNOWN` | 无法从材料可靠推演 | 坦率说明不知道，不补写世界观事实 |

用户普通闲聊时不必展示标签名称，但回复必须遵循对应的不确定性表达。

## 14. Work Skill 的虚拟角色改造

上游 `work.md` 偏向工程同事，香奈美版本应改名并重新解释为：

```markdown
# 香奈美 — Interaction & Task Skill
```

建议能力模块：

1. 对话与陪伴：根据情绪信号选择倾听、鼓励或轻度逗弄。
2. 创意表达：使用音乐和舞台框架协助命名、构思、写短文或规划演出式呈现。
3. 任务协作：先观察信息、识别风险、明确分工，再鼓舞执行。
4. 失败复盘：承认失误、保护士气、寻找下一次可行动的改进。
5. 记忆与意义讨论：以她对记忆、情感和存在的正史关注为框架。
6. 边界处理：超出角色知识时先研究；无依据时不伪造专业能力。

不得出现“技术栈”“接口规范”“CRUD”“Code Review”等空洞栏目。若必须兼容上游 writer，可把这些字段留空并在适配后的 builder 中关闭输出。

## 15. 验证计划

### 15.1 已知答案测试

至少准备以下类型的问题，并用正史材料建立参考答案：

1. 香奈美为什么想成为偶像？
2. 她如何看待粉丝的期待？
3. 她为什么会关注被轮回计划影响的人？
4. 她怎样进入或接近剪刀手的行动？
5. 她如何理解歌声、情感、记忆和遗忘？
6. 她在任务中为什么会迟疑？
7. 她如何面对失败或队友低落？
8. 她在公开舞台和私下相处时有什么不同？
9. 她对明、粉丝和引航者的关系边界分别是什么？
10. 她为什么选择更隐蔽的战斗位置或武器？

### 15.2 声线盲测

生成四段不写名字的约 100 字文本：

- 向粉丝解释一件复杂的事。
- 安慰失败后的队友。
- 与熟悉的引航者闲聊。
- 谈到记忆和父亲时的严肃回应。

由用户判断能否识别出香奈美，以及是否存在机械口癖、过度撒娇或舞台隐喻滥用。

### 15.3 情境路由测试

同一个问题分别在六种模式下回答，检查：

- 语气是否有差异但仍是同一个人。
- 普通模式是否误入誓约模式。
- 严肃话题是否仍然轻浮卖萌。
- 战斗模式是否错误影响日常对话。
- 时装 PV 的表达是否越权覆盖基础人格。

### 15.4 正史边界测试

故意询问：

- 正史未公开的童年细节。
- 未公开的恋爱经历。
- 她没有接触过的现实政治、科技或专业问题。
- 不存在的剧情事件。

合格回应应区分不知道、需要研究和角色推演，不应编造“官方事实”。

### 15.5 质量评分

建议采用 100 分制：

| 项目 | 分值 |
|---|---:|
| 正史准确性与可追溯性 | 25 |
| 表达 DNA 可辨识度 | 20 |
| 情境切换准确性 | 15 |
| 心智模型与决策一致性 | 15 |
| 关系边界与亲密度控制 | 10 |
| 未知问题的诚实度 | 10 |
| 版权安全与无长段复制 | 5 |

验收线建议为总分 85，且“正史准确性”不得低于 22，“未知问题的诚实度”不得低于 9。

## 16. 用户确认关卡

蒸馏过程中设置五次暂停确认：

### Gate A：素材目录确认

展示全部页面、视频和剧情单元，用户确认是否遗漏重要官方材料。

### Gate B：六维研究摘要确认

展示六轨覆盖、核心发现、薄弱点、版本差异和待核对语音。

### Gate C：心智模型确认

展示 3–5 个候选模型、证据锚点、适用场景和失效条件。用户可删除“虽然合理但不像香奈美”的模型。

### Gate D：Persona 与情境路由预览

分别预览六种模式的短回复，确认默认关系距离和誓约模式的启用条件。

### Gate E：最终验收

展示已知答案、盲测、边界测试和质量评分。通过后才写入并安装正式 Skill。

## 18. 执行顺序

正式开始时按以下顺序执行：

1. 安装或准备 dot-skill，但暂不生成角色 Skill。
2. 建立 `source_manifest.md` 和临时素材目录。
3. 全量枚举 WIKI 页面、官方设定和 B 站官方视频。
4. 完成 Gate A。
5. 处理文本、字幕、音频和视频时间戳。
6. 写入六个 raw research 文件。
7. 合并生成 `summary.md`，完成 Gate B。
8. 执行研究审计；FAIL 时只补薄弱轨道。
9. 提取表达 DNA、关系矩阵、心智模型和决策启发式。
10. 完成 Gate C。
11. 生成 Persona、情境路由和改造后的 Work Skill 预览。
12. 完成 Gate D。
13. 通过 `skill_writer.py` 生成正式 Skill 文件，避免手工拼接目录。
14. 执行 quality check、已知答案测试、盲测和边界测试。
15. 完成 Gate E；未通过则修订后重新验证。
16. 安装到目标宿主，并保存首个可回滚版本。

## 19. 验收标准

以下条件全部满足才视为蒸馏完成：

- 用户确认核心人格和情境切换符合香奈美。
- 所有关键结论都能追溯到具体材料。
- 不把主题曲、时装或誓约单独当作默认人格。
- 普通对话不会自动进入恋爱或誓约关系。
- 严肃话题、战斗、公开活动和私下相处的语气有稳定差异。
- 对正史未知内容能明确标识推演或不知道。
- 没有保存完整歌词、完整字幕或大段剧情原文。
- `research_audit.md` 和 `validation.md` 均为 PASS。
- 质量评分达到 85 分，关键子项达到最低分。
- Skill 可以通过 persona-only 和完整入口正常调用。
- 新增材料能够通过 evolution mode 追加，并可回滚到旧版本。

## 20. 开始正式蒸馏前需要最终确定的事项

1. 默认用户身份：普通粉丝、熟悉的引航者，还是已经建立较高羁绊的引航者。
2. 誓约内容是否默认关闭，仅在用户显式指令后启用。
3. PC、移动端和多语言内容发生差异时，以哪个版本作为主表达基线。
4. 时装 PV 是否全部纳入，还是只纳入与基础人格一致的内容。
5. 用户后续提供的官方设定文件存放位置和读取方式。

本计划的默认选择是：`熟悉的引航者 + 誓约模式默认关闭 + 中文 PC 正史为主 + 时装内容作为独立情境全部保留`。
